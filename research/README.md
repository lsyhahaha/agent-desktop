## 学习后对本项目的判断

以下是结合本地代码得到的判断与建议，尚未实施新功能。

1. **进化记录落库是证据基础，不是学习机制本身。** 现有[记录存储](../docs/evolution-storage.md)保存人工工程改进，但Runtime尚未按任务检索这些经验，更没有自动搜索、评估并部署候选。不要把记录存在等同于已经实现Reflexion、SICA或DGM。
2. **接下来先补评估可信度。** 上一轮[真实单次对照](../docs/self-evolution-1.md)的请求数/tokens改善值得继续研究，但工作树有变化、样本只有一次。应固定项目快照、任务和预算，记录任务覆盖、误报、失败及资源，再做多次比较。
3. **正确性约束优先于便宜。** 少读源码也能降低tokens，却可能漏掉行为变化。先守住权限、取消、事实归属和关键新增文件覆盖，再比较成本；模型自评不能单独决定候选是否胜出。
4. **策略候选应与正式运行分开。** 可以先研究提示词/读取策略的小范围候选，再讨论修改Runtime的候选；候选修改不能顺便改评价标准或审批边界。正式采用前仍需项目规定的比较、审批和验证。
5. **保留失败证据和适用范围。** 失败候选、任务类型、模型/工具预算、代码版本、评价来源以及原始结果应可追溯，避免把随机波动当作进步。哪些字段需要扩展，应从实际评估流程决定，不为论文先建一个通用进化平台。

建议最先补的研究题：固定同一代码快照，比较“原取证策略”和“第1轮策略”，检查除了轮数减少之外，新文件覆盖是否更稳定、错误归属是否减少。该建议不授权新增单元测试、真实付费请求、依赖或自动修改；本次只新增research材料，不改应用代码和数据库中的能力/验证记录。

## 使用与核验

- `papers/`：原文PDF，保持原样；权利归原作者，均按来源标注CC BY 4.0并保留作者与链接。
- `notes/`和`coding-self-modification.md`：中文阅读笔记、自我解释题与项目适配分析。
- `sources.json`：固定版本和本地校验清单；后续更新应新增版本或显式更新来源记录，不能悄悄替换PDF后保留旧笔记结论。
- `references.bib`：五篇文献的BibTeX，year采用首次提交年份，具体阅读版本日期另列note。

本次核对了官方页面元数据、PDF文件签名/完整结尾、文件摘要及本地引用，并使用本机PDFKit成功解析全部5份PDF（19、54、41、18、72页；具体对应见sources.json），未安装额外PDF依赖。正文阅读使用arXiv官方HTML对应版本；没有安装或运行作者仓库，没有新增付费模型调用，没有将论文结果视作Agent Desktop的实测能力。
