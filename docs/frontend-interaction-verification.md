# 前端布局与交互检查（2026-10-31）

本轮针对用户两张截图，修改App.tsx和style.css，复用现有React/CSS；未改Runtime、权限策略、PTY执行、协议或存储，没有新依赖、事件监听器或单元测试。

## 已复现与修复

1. **底部按钮覆盖输入区。** 触发条件是已有对话、模型已配置、侧栏收起、终端分栏打开。三个全局按钮原来固定在窗口底部，侧栏收起后没有所属布局空间；分栏输入框靠左时与其相交。未配置模型的提示会抬高输入框，空白页也采用另一种布局，因此这些状态不能代替复现。真实Electron几何检查修复前返回“展开侧栏、设置、换肤”三个重叠按钮；修复后无相交，中心点击命中正确按钮。改为统一nav和Grid工具行，折叠时工作面占首行、工具占第二行；展开时工作面跨两行、工具位于侧栏底部。
2. **标题侵入macOS窗口按钮区域。** 分栏紧凑header样式覆盖折叠后的安全区，最大化终端也未保留。修复前聊天和最大化终端标题起点均为x=23；修复后明确保留94px内边距，原复现检查通过。Electron原生窗口按钮不在页面DOM中，本次检查其设计预留区，截图来自实际窗口内容。
3. **新任务页靠上。** 固定顶部padding和普通文档流不利用下方空间。默认窗口下，输入区中心位于聊天可用高度的38.7%，用户看到下方大片空白。改为首尾auto margin共享剩余空间，欢迎区降低固定padding；修复后约50.2%。不足时margin归零，不使用transform强行居中导致顶部不可达。水印居中缩放并限制在欢迎区，避免跨到输入框。

## 实际验证

- `npm run build`（含TypeScript检查）、`git diff --check`通过。
- 使用Playwright启动真实Electron45.1.0，独立临时userData，模拟Provider返回少量对话数据，实际Renderer/Runtime/SQLite；不访问真实项目或付费模型。
- 32种布局组合：空任务/已有对话 × 1360×860/1000×680 × 浅色/深色 × 侧栏展开/收起 × 终端关闭/打开。检查无全局横向溢出、输入区可见、全局按钮不与输入框相交、按钮中心点击命中正确、空页输入区位置合理、分栏标题安全区。
- 每种组合实际打开设置、换肤和权限弹层，检查边界位于窗口内，Escape关闭；主题通过真实换肤按钮切换。
- 原遮挡复现另验终端最大化/还原及标题安全区；浅深色截图人工检查。终端未选目录状态用于分栏布局，不把此验收称为真实PTY命令回归。

## 范围与成本

本轮是布局检查，不是完整前端功能审计。未重测真实模型流、所有审批状态、文件操作、PTY命令控制、超长对话性能或其他操作系统。最小窗口以Main规定的1000×680为准；没有新增持续计算、网络请求或存储开销。侧栏收起时底部约50px成为独立工具行，这是避免按钮覆盖内容所需的可见布局空间。
