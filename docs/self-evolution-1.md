# 自进化第1轮：按任务目标取证，减少无效往返

日期：2026-11-01。分支design/agent-observability，基线提交d847ae8之上的未提交工作区。

这里的“自进化”是用户命名的工程改进过程：真实轨迹 → 定位问题 → 修改Agent Desktop → 受控验证 → 获得明确授权后的真实复测 → 记录收益与缺口。本轮由开发助手实施并人工审阅，不是产品具备自动修改、提交或部署自身代码的能力。

## 需求与证据

用户问“看看当前代码改了哪些什么？”，目标是改动概览，不默认等于逐文件深入审查。前次真实轨迹用了10轮模型/10次工具/117640输入tokens，最后被预算要求总结；两个关键新增模块未深入读取。审批等待与模型耗时分别约17.5秒和16.2秒，因此仅提高请求上限不能解决取证选择与往返次数问题。

参考：[前次真实记录](evidence/observability-live-10.json)。本次授权仅一次真实DeepSeek只读复测，执行中保留现有权限/审批，没有扩大模型或工具预算。

## 实际修改

### 任务策略与取证顺序

- Agent的可信系统提示明确区分改动概览、深入审查、修改与验收，遵循用户指定的比较基线；未指定时关注未提交的暂存、未暂存、未跟踪三类状态。
- 改动概览先取Git状态与文件统计，不强制先遍历全项目；优先关键新增源码和行为契约，普通git diff不能代表未跟踪文件内容。
- 数个独立查询在同一模型响应提出，复用原有多工具协议；Runtime仍串行执行、分别校验与审批，不引入并行副作用调度。
- 明确head/sed等输出只是片段，truncated=false仅表示执行器未触发输出上限，不证明源文件完整读取。信息足以回答概览时直接总结，保留未检查范围，不等到上限；深入任务不能套用概览的浅层完成标准。
- 每次请求额外带Runtime生成的剩余轮数/工具数提示，该提示仅用于当次请求，不追加到后续成功模型历史。没有关键词任务分类器、额外规划模型或LLM裁判。

这是工作策略提示，不能保证模型永远遵循，也不是Runtime自动证明任务完成。原始工具输出仍完整保留，没有实现上下文压缩、全仓快照或历史删减。

### 批次接纳与终态

- 每个模型响应先检查全部工具ID，重复或与此前已接纳ID冲突时，在本批任何工具执行前拒绝，避免执行一半才发现重复。
- 10次主模型和12次工具预算保持不变。若同批工具超出剩余12次接纳额度，超额部分逐一产生“未接纳/未执行”的时间线、日志及模型工具结果；不触发审批、进程或文件访问。
- 未接纳调用不写入上限12条的执行审计，不冒充执行失败或成功。模型声明仍逐一有配对结果，下一轮禁用工具、总结已有事实与缺口；原始参数不因未执行而静默丢失。
- 前端将“已接纳工具调用”和“预算未接纳调用”分开显示；完整命令日志、取消、超时、持久化及权限边界不变。

代码入口：apps/runtime/src/agent.ts、tools.ts、apps/desktop/renderer/src/Observability.tsx。无新依赖、数据库迁移或跨进程接口；仅复用既有工具、状态和日志字段。新增策略带来少量每请求提示开销；没有测得常驻内存变化，不宣称零开销。

## 复用与未实施项

项目已具备多工具响应、受限Shell、read_file、目录读取、日志与时间线，本轮直接复用并调整其调用策略。未引入Git SDK，也未编写新的免审批Git执行通道。结构化Git查询仍是后续候选，必须先比较原生CLI适配与SDK方案，评估配置触发外部程序、路径、输出与取消边界，并按AGENTS.md获得方案批准。不能为了降低审批次数把任意git命令加入免审白名单。

## 实际验收

npm run build含类型检查、git diff --check。没有新增单元测试。

[定向受控集成](evidence/self-evolution-1-controlled.json)：真实Electron45.1.0/Runtime/SQLite/Renderer，临时HOME和项目，Provider及凭据为替身。11次读取后再请求3个工具：只接纳第12次，剩余2次未执行、结果逐一配对，最终正常总结；副作用哨兵文件不存在。同批重复ID在任何工具启动前失败。截图：[预算未接纳](evidence/self-evolution-1-budget.png)。既有24项可观测性受控回归另见[evidence/observability-acceptance.json](evidence/observability-acceptance.json)。

[本轮真实运行](evidence/self-evolution-1-live.json)：真实已配置DeepSeek与正式凭据解密、实际项目只读工具，隔离userData，不关闭原有用户实例。复测后删除临时拷贝的加密设置，没有打印或保存明文Key。工具序列、完整命令/参数及原始回答保存在证据中，API调用仅本次。

**适用限制：** 两次执行之间工作区代码和证据文件有变化，本轮还包含策略与预算修复；不是固定快照、多次随机重复或单变量消融实验，不能据此承诺稳定平均提升、因果归因或任务正确率。审批等待受交互时机影响，不比较总耗时。

输出仍有缺口：CSS与部分文档未深入读取，时间线Diff只读片段；个别实现归属表述不准确（版本分支在App，ChatCommand的index在packages/protocol），需人工校对。既有构建与受控检查证明实现对应范围，不证明真实模型回答全面正确。未覆盖全平台、长期压力、全部故障窗口或完整读屏软件。
