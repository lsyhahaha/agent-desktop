# 自主项目探索修复与验收（2026-10-31）

## 根因与最小改动

修复前一次性复现直接调用真实modelStep并捕获请求：`actual_model_tools=read_file`，断言list_directory存在时失败。静态核对还发现Agent只允许read_file。循环本身已有模型—工具—模型能力，因此保留Runtime、会话调度、流解析、取消和运行预算，只补能力与注册。

- tools.ts是唯一工具注册目录，模型JSON Schema从现有Zod定义生成；执行端也从此目录解析工具名与参数。
- list_directory通过Node内置opendir有界广度优先遍历，默认深度2、最大3，最多160个条目/400次扫描/约16KiB条目预算。截断显式返回truncated，不宣称全量覆盖；排除隐藏/凭据、链接、依赖与构建目录。
- workspace-path.ts复用并统一目录/文件的相对路径、真实路径、逐级链接与设备检查。read_file保留32KiB、UTF-8、普通文件、硬链接拒绝、文件身份复验和逐次审批。
- 系统指令要求分析项目时先列目录，再自主选README、配置与核心源码。目录枚举依据原生工作区选择授权；文件内容仍逐次审批。
- UI只保留一次可读角色名称，头像aria-hidden；压缩多余空行，正文右侧保留空间。没有引入Markdown解析库或新依赖。
- completed只表示本轮执行完成，任务完成由用户确认单独记录；后续输入重新打开任务。等待授权、取消和失败分别呈现，工具记录展示名称、状态与摘要。

## 真实DeepSeek验收

用户授权重启后，选定 `/private/tmp/agent-exploration-live` 非敏感样例项目，唯一用户任务输入为“看看当前项目”，没有提供任何文件名。

实际工具顺序：

1. list_directory，路径“.”，成功列出5个条目。
2. read_file package.json，125字节。
3. read_file README.md，249字节。
4. read_file src/index.ts，153字节。
5. read_file src/store.ts，208字节。
